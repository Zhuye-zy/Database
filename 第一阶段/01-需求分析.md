# 01 · 需求分析（A角色，对应报告模板“需求分析”章初稿）

> 本章可作为小组报告“需求分析”整章的初稿；术语与 `02-实体与属性清单.md`、`03-实体关系分析.md`、`04-ER图.md` 一致。

## 1. 项目背景与选题意义

### 1.1 选题
以**专利数据服务试验系统**（http://patdata.cnipa.gov.cn/）提供的四类数据为研究对象：

1. 美国专利申请公布全文文本数据（US Application Full-Text，文献种类如 A1）；
2. 美国专利授权公告全文文本数据（US Grant Full-Text，如 B1/B2，外观设计 S1）；
3. 欧洲专利全文文本数据（EP Full-Text，如 EP A1/B1）；
4. EP 专利摘要（DOCDB）数据。

参考其数据手册与样例 XML，设计一个**本地存储关系数据库**，为后续专利数据分析和挖掘（技术领域分布、申请人排名、引用网络、同族分析、时间趋势等）奠定基础。

### 1.2 专利数据的特点（为什么值得单独设计数据库）

| 特点 | 具体表现（样例/规范证据） | 对数据库设计的要求 |
|---|---|---|
| **多值属性密集** | 一件专利可有多个申请人、发明人、分类号、权利要求、引用；官网授权样例单篇 `us-citation` 最多 **690** 条、`claim` 最多 33 条、IPC 最多 8 条、发明人最多 3 人 | 全部 M:N/1:N 拆表，禁止多值留在单行 |
| **引用网络 + 自引用** | citing 与 cited 都是专利/文献；被引常常不在本地库（官网样例可见任意国别，EP 引用为纯文本） | `patent_citation` 双外键自引用 patent，库外文献保留国别/号码/种类/日期，非结构化引用存 `cited_raw_text` |
| **专利族** | 同一发明在多国申请，DOCDB/INPADOC 两种族口径 | 族表 + 成员表（M:N），支持多族类型 |
| **长文本** | 摘要、权利要求、说明书全文（单篇可达数百 KB），描述内嵌 b/i/figref 等标签 | TEXT/LONGTEXT；说明书按章节/段落拆分 |
| **多国多语言** | 标题/摘要多语言（EN/DE/FR），国家码/种类码/语言码均为标准代码 | 语言维表 + 带 lang 的标题/摘要表 |
| **标准驱动** | INID 码（ST.9）、国家码（ST.3）、种类码（ST.16）、XML 标准（ST.36/ST.96） | 维表化代码，字段与标准可追溯 |
| **数据量大** | 四类数据年增量百万级、单文件批量拼接 | 批量导入、索引与分区、代理键 |

### 1.3 课程与工程意义
- 覆盖《数据库实践》大纲要求：需求分析（用例图/数据流图/数据字典/E-R 图）→ 数据库设计（规范化、基本表）→ 完整性/安全性（约束、触发器、视图、索引）→ 数据库实现 → 应用实现。
- 训练复杂工程问题：**异构 XML → 规范化关系模式**的 ETL 设计、自引用与多值建模、大规模文本与索引优化。
- 数据库选型兼顾国产信创（openGauss）与主流系统（PostgreSQL/MySQL），本设计给出可移植 DDL 建议。

## 2. 需要解决的工程问题

1. **XML 批量解析与清洗**：USPTO 批量文件是多篇文档直接拼接（非合法 XML，见 `sources/XML结构解析报告.md`），需切分/流式解析；日期存在 `YYYYMM00` 月精度；文本含 XML 实体；多文档按局/种类分流。
2. **概念模型设计**：从著录项（INID）与全文结构中提炼实体，解决多值、自引用、长文本、多语言、专利族等问题，产出 E-R 图与数据字典。
3. **规范化与完整性**：满足 3NF，键/外键齐备；自引用（引用、从属权利要求、分案/继续、优先权、章节树）与库外引用不能破坏约束。
4. **可分析性**：支持申请人/发明人检索、IPC/CPC 分类统计、引用网络查询、同族检索、法律状态与时间趋势分析。
5. **可扩展与可移植**：预留增强表（关键词、指定国、族级引用、技术领域映射），可在 PostgreSQL/MySQL/openGauss 间迁移。

## 3. 功能需求（用例）

| 编号 | 功能 | 参与者 | 说明 | 主要涉及表 |
|---|---|---|---|---|
| F1 | 导入专利数据 | 数据管理员 | 解析 XML 并批量入库，支持断点/重跑、错误日志 | 全部 |
| F2 | 数据质量校验 | 数据管理员 | 去重、外键完整性、日期/号码格式、必填项统计 | 全部 |
| F3 | 按文献号/申请号检索专利 | 专利分析师 | 单篇/批量精确与模糊检索 | patent/publication |
| F4 | 按申请人/发明人检索 | 专利分析师 | 人名检索 + 该人全部专利列表 | person/patent_applicant/patent_inventor |
| F5 | 按分类号检索/统计 | 专利分析师 | IPC/CPC/USPC 层级检索、技术领域分布 | classification/patent_classification/ipc_techn_field |
| F6 | 查看引用关系 | 专利分析师 | 正向（引用了谁）/反向（被谁引用）、引用类别过滤 | patent_citation/patent_citation_category/non_patent_citation |
| F7 | 专利族分析 | 专利分析师 | 同族成员、族规模、代表文献、族级引用 | patent_family/patent_family_member/family_citation |
| F8 | 权利要求分析 | 专利分析师 | 独立/从属结构树、权利要求数量 | claim/claim_dependency |
| F9 | 法律状态与时间趋势 | 专利分析师 | 授权/失效事件、申请量年份趋势 | legal_status_event/legal_event_code |
| F10 | 说明书/摘要全文检索 | 专利分析师 | 关键词定位到段落/权利要求 | abstract/description_section/claim |
| F11 | 统计报表导出 | 专利分析师 | 申请人排名、分类分布、引用热度等 CSV 导出 | 视图 + 分析临时表 |

**需求→设计追溯**：F3→`publication(publn_auth,publn_nr,publn_kind)` 唯一约束；F4→`person` 姓名索引 + 关联表；F6→`patent_citation` 自引用双索引（citing/cited）；F7→`patent_family_member`；F8→`claim_dependency`；F9→`legal_status_event`；F10→长文本表。

### 3.1 数据流图（0 层/1 层，文字+DOT 描述）

```

  官网/样例 --(下载/人工获取)--> D1
```

## 4. 数据需求

### 4.1 数据内容（数据类型）
- **著录项目**：申请号/申请日、公布号/公布日/种类、申请人、发明人、权利人、代理人、审查员、优先权、分类号、引用、PCT/区域信息、指定国、法律状态。
- **全文文本**：标题、摘要、权利要求、说明书章节、附图引用。
- **族与关系**：DOCDB/INPADOC 族、族成员、族级引用、国内程序关联（分案/继续/再颁）。

### 4.2 规模估计（**量级估算**，依据公开年增量的数量级；官网手册到手后须复核）

| 数据对象 | 单年度估算 | 全量（多年）估算 | 说明 |
|---|---|---|---|
| 美国申请公布 | 约 40 万篇/年 | 数百万~千万 | A1 周更，单篇 XML 约 50–200KB |
| 美国授权公告 | 约 30–35 万篇/年 | 数百万 | B1/B2/S1 |
| EP 全文 | 约 10–20 万篇/年 | 数百万 | A1/B1 |
| EP DOCDB 摘要 | 百万级/年（覆盖多局） | 数千万~亿级 | 以摘要/著录为主 |
| 原始 XML 总量 | 数十 GB~百 GB/年 | 数百 GB~TB 级 | 文本为主，图件另存 |
| `patent` | 约 100 万行/年 | 千万行 | 多数据集合并去重 |
| `publication` | 约 200 万行/年 | 数千万行 | 一申请多文献 |
| `claim` | 约 2000 万行/年 | 数亿行 | 长文本主体 |
| `patent_citation` | 约 1000–3000 万行/年 | 数亿行 | 引用网络 |
| `description_section` | 约 1 亿行/年 | 十亿级 | 按段落拆分的最大表 |

> 结论：**本地库按“可扩展大数据量”设计**——代理主键 BIGINT、长文本分离、批量导入 + 索引后置 + 必要分区（按申请年或局代码），C 阶段用单年度子集验证。

### 4.3 数据来源与合规
- **官网来源（已获取）**：专利数据服务试验系统四类数据的数据手册与样例（US-PA-TXTO-10-A、US-PA-TXTO-10-B、EP-PA-TXTO-10-AB、EP-PA-ABSO-10-AB，由组员下载，归档于 `sources/官网资料/`、`sources/samples/官网/`），本设计已按手册与样例逐项核对（见 `02` §8）；
- 标准与交叉验证：WIPO ST.9/ST.3/ST.16/ST.36/ST.96、EPO PATSTAT/DOCDB 公开表结构（第三方镜像）、USPTO 新版样例（v4.6/v4.7，版本差异对照）；
- 合规：不伪造身份注册、不绕过验证；样例仅用于课程内结构分析。

## 5. 设计约束（课程硬性要求 + 技术约束）

1. **表数量 ≥20**：本设计 43 张（核心 38 + 增强 5），即使不实现全部增强表，38 张核心表仍满足要求；详见 `03-实体关系分析.md` §3.2。
2. 满足 **3NF**：见 `03-实体关系分析.md` §3（含受控冗余披露）。
3. 体现**键/外键**：主键 38 组、外键 60+ 个（含自引用 6 组、复合外键 3 组）。
4. DBMS 选型：优先 **PostgreSQL**（TEXT、GIN 全文检索、DEFERRABLE 约束适合自引用）或 **MySQL 8**（LONGTEXT、FULLTEXT，部署简单）；**openGauss** 作为信创备选（兼容 PostgreSQL 语法，需确认 `TEXT/GIN/IDENTITY` 支持）。
5. 数据完整性：非空、唯一、外键、CHECK（如 `publn_date >= appln_filing_date` 弱约束可用触发器）；自引用延迟约束。
6. **设计方法约束**：概念设计（E/R 模型、弱实体集、ISA 子类）与逻辑设计（E/R→关系转换、函数依赖与 BCNF/3NF/4NF 分析）严格按教材《数据库系统基础教程（原书第3版）》第3、4章的方法执行，映射过程见 `03-实体关系分析.md` 与 `04-ER图.md`。
6. 安全与权限：导入账号与查询账号分离（最小权限），只读视图供前端列表。

## 6. 非功能需求

| 类别 | 需求 | 验收方式（C 阶段） |
|---|---|---|
| 性能 | 单篇专利入库 ≤ 0.5s（批量 1 万篇 ≤ 30min）；常用检索 ≤ 2s（百万级） | 导入计时、EXPLAIN ANALYZE |
| 可扩展 | 新增数据源/国家不修改核心表；维表可插拔 | 增加 EP 数据不重建核心表 |
| 可分析 | 支持多表 JOIN、全文检索、聚合统计视图 | 完成 5 个以上分析查询（D 负责成果化） |
| 可靠性 | 导入可重跑（幂等：唯一约束 + UPSERT）；失败可定位 | 重复导入不产生脏数据 |
| 可维护性 | 字段/表有中文注释与来源；脚本有注释 | 数据字典与库内 COMMENT 一致 |
| 安全合规 | 不使用真实个人隐私推断；数据来源注明；不绕过官网授权 | 文档审查 |

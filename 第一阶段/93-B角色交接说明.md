## 3. 建表顺序与关键约束

建议顺序：

```text
维表
  → patent
  → publication
  → 标题/摘要/权利要求/说明书/附图等文献弱实体
  → person 与 ISA 子类
  → 人员角色、分类、引用
  → 专利族、族成员及三个族子表
  → 优先权、程序关联、法律事件
  → 增强表
```

B 必须落实：

- 所有 PK、FK、NOT NULL、UNIQUE 和必要 CHECK；
- 复合外键：`publication(publn_auth,publn_kind)`、`patent_classification(scheme_code,symbol)`、`legal_status_event(event_auth,event_code)`；
- 弱实体使用代理主键，同时将“属主键 + 部分键”设为 UNIQUE，并按需要使用 `ON DELETE CASCADE`；
- `natural_person`、`organization` 的主键同时外键引用 `person`；通过触发器或等价机制保证 `person_type` 与子类一致；
- `patent_citation.citing_publication_id` 非空；被引专利、族成员可能在库外，解析外键可空，但原始号码不得丢失；
- 文本列按目标数据库选择 `TEXT`/等价大字段类型，禁止把权利要求和说明书截断为短 `VARCHAR`。

## 4. 批量解析与导入规则

1. USPTO 批量 XML 可能由多篇 XML 文档直接拼接，先切分逻辑文档，再解析单篇。
2. DOCDB 的 `exchange-documents` 是包装根；应逐个 `exchange-document` 导入。
3. 多值元素必须逐行写入关联表或弱实体表，不得拼接成一个可查询字段。
4. EP 权利要求按 `claims/@lang` 分套保存，唯一性至少包含 publication、语言和权利要求编号。
5. 日期同时保留解析列和必要的 `*_raw`：完整 `YYYYMMDD` 才转 `DATE`；`YYYYMM00` 不伪造日；`9999-12-31` 哨兵转 NULL 并保留原文。
6. 导入应幂等：利用业务唯一键、UPSERT/等价机制避免重复运行产生重复数据。
7. 失败记录至少包含数据集、源文件、逻辑文档标识、XML 路径、错误类型和错误消息。

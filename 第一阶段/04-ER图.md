## 3. 六个域的概念语义

### 3.1 著录与文献

- `patent` 是申请案，`publication` 是具体公布/公告文献；一件申请可有多份文献，一份文献属于一件申请。
- title、abstract、claim、drawing、description_section 依赖 publication 才能识别，按教材定义画作弱实体集。
- claim 的从属关系和 description_section 的父子关系均为一元递归联系，图中标出角色。
- 语言、文献种类、受理局等代码实体通过多对一联系并入物理关系；完整清单见 `03` R01–R21。

### 3.2 人员与角色

- person 是 ISA 超类；natural_person 与 organization 为全覆盖、互斥子类。无法可靠判型的源记录必须留在导入暂存区，不能同时随意写入两个子类。
- 申请人、发明人、权利人、代理人、审查员是 patent 与 person 之间五个不同的 M:N 联系，不是五种 person 子类。
- sequence、designation、role、rep_type、department 是联系属性；转换后分别进入五张关联表。

### 3.3 分类

- classification 的键为 `(scheme_code, symbol)`，分类符号自身分量存强实体；position/value/source_type 等只描述“某申请采用某分类”的事实，属于 M:N 联系属性。
- ipc_techn_field 是可删增强实体，以虚线表示外部映射，不改变核心概念模型。

### 3.4 引用

- XML 引用清单属于具体 publication，故先建“引用出现”弱实体，部分键为 `(citation_type, citn_seq)`；这是上一版缺少 `citing_publication_id` 后无法区分不同公布文本引用清单的修正。
- 解析成功时，引用方/被引方形成 patent 上的一元递归 M:N 联系；两端明确标注角色。
- 被引专利可能不在本地库。此时只保留外部国别、号码、种类、日期原文，`cited_patent_id`/`cited_publn_id` 为空，不伪造库内实体。
- 非专利文献和引用类别分别通过 1:1、M:N 联系保存。

### 3.5 专利族与程序关系

- patent_family 拥有 family_member 弱实体；DOCDB 一个 family-member 下可有多种格式的 application-reference 和多份 publication-reference，故继续用两个弱实体集保存，不能压成一列。
- `patent-family/abstract` 属于专利族，不属于当前 exchange-document，故单独建 family_abstract 弱实体。
- 库外族成员仍保留申请号/公布号引用；仅在匹配成功后由可选联系解析到本地 patent。
- 优先权、程序关联、族级引用均为一元递归联系并标注角色；指定国为 patent 与 country_office 的 M:N 联系。

### 3.6 法律状态与关键词

- legal_status_event 以 patent 为属主、event_seq_nr 为部分键；event_code 指向事件码实体。
- keyword 为增强实体，与 patent 构成 M:N 联系；weight/source 是联系属性。

## 4. E/R→关系的可追溯映射

| E/R 构造 | 转换结果 |
|---|---|
| 强实体集 | dataset、patent、publication、person、classification、patent_family 等强实体表 |
| 弱实体集 | title、abstract、claim、drawing、description_section、legal_status_event、patent_citation（citation occurrence）、patent_family_member、family_member_application_ref、family_member_publication_ref、family_abstract |
| person ISA | person + natural_person + organization（教材 4.6.1 的 E/R 方式） |
| 人员五种 M:N 联系 | patent_applicant / patent_inventor / patent_assignee / patent_agent / patent_examiner |
| 申请—分类号 M:N | patent_classification |
| 引用递归联系及其出现属性 | patent_citation；来源文献键、两端申请键和库外标识同表实现 |
| claim 递归依赖 | claim_dependency |
| 族成员与号码弱实体 | patent_family_member + family_member_application_ref + family_member_publication_ref |
| 优先权/程序关联/族引用 | priority_claim / related_application / family_citation |
| 指定国/关键词 M:N | designated_state / patent_keyword |

逐表主键、外键、唯一约束和教材规则见 `03-实体关系分析.md` §3.2 与 `02-实体与属性清单.md` §7。转换结果共 **43 张表、345 个字段**。

## 5. 渲染与一致性验证

```bash
python3 sources/scripts/gen_er_textbook.py /tmp/er-out
rsvg-convert /tmp/er-out/ER教材-总览.svg -o /tmp/er-out/ER教材-总览.png
```

验收点：SVG 必须能被 XML 解析器读取；drawio 必须包含 6 个 `<diagram>` 页面；PNG 非空；图中不得出现 crow's foot 符号。关系模式辅助图仍保留 crow's foot，但文件名明确为 `04-关系模式图-*`。

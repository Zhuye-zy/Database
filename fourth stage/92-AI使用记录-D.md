# 92 · AI 使用记录（D 角色）

> 与 `第一阶段/92-AI使用记录.md`、`third stage/92-AI使用记录-C.md` 同一体例：如实记录本阶段 AI 的参与范围、人工核验方式与 AI 的局限，供报告第 5.4 节「AI 使用声明」引用。

## 1. 使用的 AI 工具

| 工具 | 用途 |
|---|---|
| AI 编程助手 | 分析 SQL 草稿与审阅、图表脚本、docx/PPTX 生成脚本、报告与讲稿文字初稿 |
| 说明 | 未使用 AI 生成任何「官方手册内容 / 页码 / 样例数据」；未使用 AI 编造库内不存在的结论或数字 |

## 2. AI 的具体贡献（按交付物）

| 交付物 | AI 贡献 | 人工（D 角色）核验 / 判断 |
|---|---|---|
| `03-分析挖掘/sql/*.sql`（5 主题 21 条） | SQL 草稿、口径说明与注释 | 逐条在库内执行并核对结果；判定「被引热度」不可做，改为引用方结构 |
| `03-分析挖掘/make_charts.py` 与 6 张统计图 | 图表结构、配色与标注草稿 | 核对每张图的数据与 `analysis_results.json` / CSV 一致；检查中文显示与坐标标签 |
| `01-设计文档/report_content.py` | 五章正文文字草稿、表格化组织 | 逐段对照仓库证据文件与各阶段文档；改写不准确的表述（如「被引次数」→「引用方结构」） |
| `01-设计文档/build_report.py` | docx 生成脚本（块渲染、模板样式套用、自检） | 解析模板确认页面/字体/编号规则；核对生成结果与模板一致，自检脚本全绿 |
| `02-汇报PPT/build_ppt.py` | PPT 结构、版式与讲稿草稿 | 核对每页数字与报告一致；人工确认讲解顺序与时长 |
| 流程图 / 框图（第四阶段 04 目录） | 图形结构与文字草稿 | 核对图中表名、约束数、流程分支与实际脚本一致 |

## 3. AI 出过的问题（如实披露）

1. **数字不一致**：早期草稿把分析 SQL 写成 19 条、申请人条目写成 15 个；人工与证据文件对照后发现，改为由脚本从证据文件注入数字。
2. **字符串拼接错误**：申请人数的表达式对字符串做「+」，输出「610 个」；人工检查生成文档时发现并改为 `int()` 相加。
3. **格式细节**：模板一级标题依赖 `numId=5` 的自动编号，AI 初稿自行编号会导致「一、一、」重复；改为沿用模板编号。
4. **越界结论**：AI 初稿出现「行业趋势」「被引热度」等超出样例规模的表述，人工按「只用数据支撑的结论」原则全部删除或改写。
5. **图表字体**：AI 默认字体在无中文字体的环境渲染成方框，人工补充字体族指定后才可交付。

## 4. 结论

AI 在本阶段主要承担「脚本与文字初稿」，全部事实、数字与结论均由组员对照仓库内证据文件（`逐表行数.json`、`*_result.json`、`analysis_results.json`、数据库现场查询）核验后才写入报告与 PPT。凡 AI 无法确证的内容（库外被引文献、官方族号、样例未给出的组织信息）一律留空并在报告第 4.7 节声明。

## 5. 可复现性

本阶段所有产物都可由脚本重新生成：

```bash
python3 "fourth stage/03-分析挖掘/run_analysis.py"   # 21 条分析 SQL → CSV/JSON
python3 "fourth stage/03-分析挖掘/make_charts.py"    # 6 张统计图
python3 "fourth stage/04-流程图与框图/gen_diagrams.py"
python3 "fourth stage/01-设计文档/make_figures.py"   # 汇总 21 张报告用图
python3 "fourth stage/01-设计文档/build_report.py"   # 报告 docx + 自检
python3 "fourth stage/02-汇报PPT/build_ppt.py"       # 汇报 PPTX + 讲稿（含生成后自检）
python3 "fourth stage/05-打包/package_submission.py" # 提交包 ZIP + SHA256 清单
```
